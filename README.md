# Documentation portal

The generated documentation portal for the victron-venus organization. It
aggregates each project's own `README.md` and `docs/` directory into one
searchable site with a single information architecture, so a reader does not
have to know which of forty repositories holds the page they need.

**Nothing is copied into this repository.** The source of truth stays in each
project repository. This portal reads it at build time.

## Why it exists

The organization publishes 3,800 markdown files across 97 `docs/` trees, but
only eight of those trees had an index, so about 40% of the pages were reachable
from nowhere. Two copies of the same catalog competed in search results, and
239 mermaid diagrams rendered nowhere. This portal adds one navigable layer
without creating a second copy of any document.

## How it works

```
catalog.json            project list, generated by victron-venus.github.io
scripts/sync_sources.py reads each project's README.md and docs/ into docs/projects/
mkdocs.yml              theme, mermaid rendering, search
docs/                   hand-written portal pages only (index, reference, contributing)
```

`sync_sources.py` rewrites every relative link to the repository's blob view, so
a link in an aggregated page always resolves. It skips shared boilerplate
(`release-workflow.md`, `quality.md`, `openssf-evidence.md`, `VERSIONING.md`,
`runner-preflight.md`, `release-read-safety.md`, fuzzing notes): those exist in
dozens of diverging copies and the portal links the canonical source once
instead of rendering every copy.

## Local build

```sh
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock
.venv/bin/python scripts/sync_sources.py --catalog ../victron-venus.github.io/assets/catalog.json
.venv/bin/mkdocs build --strict
.venv/bin/mkdocs serve
```

Without `--clone` the script reuses the sibling working checkouts in the
workspace; with `--clone` it shallow-clones every catalogued repository into
`.sources/`. The build runs in strict mode: a broken link, an orphan page or a
malformed mermaid block fails CI rather than shipping.

## What it deliberately does not do

- It does not duplicate the hand-written guides. Those stay on
  [victron-venus.github.io](https://victron-venus.github.io/), which remains the
  single maintained copy.
- It does not publish a GitHub wiki. Wiki content is generated from `docs/` in
  the owning repository, never hand-edited here.
- It does not machine-translate. A page without a translation falls back to
  English with a visible notice rather than silently presenting a machine
  translation of identifiers such as `com.victronenergy.battery`.

## Updating the project list

Regenerate `catalog.json` from the landing page, then copy it here:

```sh
cd ../victron-venus.github.io && python3 scripts/build-catalog.py
cp assets/catalog.json ../docs-portal/catalog.json
```

The catalog is validated in that repository: the declared per-group counts must
equal the number of cards, and every card must appear in the JSON.
